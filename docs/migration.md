## URLと確認方法

公開ルート `/lab-learning/` は `/lab-learning/learning/` へ転送し、クエリ文字列とハッシュを保持します。旧リポジトリ名を含む別URLには、この転送では対応できません。研究ガイドの移行時の見出しアンカーは、対応する章へ移動します。

旧InDesignの8パスと見出しアンカーは `research/scripts/indesign-redirects.mjs` で保持しています。転送先は補足ノート内の固定IDで指定し、クエリ文字列も保持します。

`npm run check` で既存教材の検証と、研究ガイドのページ・ローカル参照・検索先・アンカー・画像を確認します。`npm run build` で両サイトを `dist/` に集め、`npm run dev` で公開時と同じパスを確認できます。

公開前にローカル表示を確認し、push後にGitHub Actionsと実際の公開URLを確認してください。

## 学番ページの自動特定

2026年9月14日、指定されたWikiの「研究進捗まとめノート」部分に、学年区分と学番・氏名をタイトルに含む個人ページのリンクがあることを確認しました。Wiki全体の応答は `truncated: true` ですが、今回参照する見出しと個人ページへのリンクは取得内容に含まれています。無関係な未対応ブロックや全学生の本文を確認したとは扱いません。

学生用プロンプトの個人ページURL入力欄を学番・氏名へ変更し、for AIマニュアルにWikiから本人のページと書き込み先を特定する手順を追加しました。学番・氏名・対象ページURLは照合結果から報告へ自動入力します。学年や個人ページ一覧は固定せず、複数候補・氏名不一致・権限不足のときだけ確認します。公開ファイルには学生個人の名前・学番・ページURLの一覧や研究内容を転載していません。今回もNotionへの実際の書き込みは行っていません。


学生向けのコードブロックを「初回」「2回目以降」に分けました。初回は学番・氏名を入力し、2回目以降は専用ページと会話の設定を引き継ぎます。プロンプトにGitHub Pages公開先のfor AIマニュアルURLを埋め込み、マニュアル内の研究ガイド参照も絶対URLにしました。マニュアルのURLはこのリポジトリのGitHub Pages配信先です。公開の成否はActionsの結果と実際のURLで確認します。

for AIマニュアルの報告仕様を固定しました。C1〜C6の確認結果、P1〜P3の優先度、確認状態と対応状態を区別し、各問題に根拠・研究への影響・課題・次の行動・解消条件を必須としています。報告テンプレートはマニュアルに同梱し、単体のURLだけで必要項目を取得できます。

追加指示により、AIが目的・現在の作業・得られる情報・足りない点を学生に説明する手順を必須化しました。教員フィードバックが未記録の場合、AIから学生に提供・記録を依頼し、原文・学生の理解・AIの解釈を分けて報告します。間接的な準備や探索を一律に目的の逸脱と判定しないよう明記しています。

公開準備では、学習資料のANOVA出力に列が追加されたため、検証コードのF値の参照を列番号から列名に変更しました。全体のチェック（学習38ルート・解析選択127通り、研究14ページ）とビルドが通ることを確認しています。

公開後の追加依頼により、記録が空・不足している場合はAIから学生へ記入項目、Notionの記入先、コピー用の記入欄、必要な理由を1〜3点ずつ示し、記入後に読み直す手順を明記しました。目的が未定の場合は対話から整理し、未実施と未記録・取得不能を区別します。記録依頼と再確認の状態を報告に引き継ぎます。

「研究状況（AI整理）」は、そのままゼミ用資料として使う位置づけに統一しました。学生は研究記録の提供と内容確認を担当し、AIが構成・説明文・成果資料への参照・問題点・相談事項を含む資料全体を生成します。初回と継続用の両プロンプト、AIマニュアル、同梱・単体の報告テンプレートを更新しています。利用AIのNotion接続、実際の資料生成・保存は未実施です。
