# ウェブインタラクション入門

2026-09-15。ウェブの構成要素を軽く一巡し、CMSが何をしているかを理解できる教材とする。最後に、インタラクションの実装手順と、表現を支える道具の幅を紹介する。

## 章構成

1. フロントエンドとバックエンド：ブラウザ・サーバー・データベースの関係。通信はURLの各部分、DNSとIPアドレス、接続、HTTPの要求と応答、HTTPS/TLS、追加リソースの取得を順に説明する。DNSの接続先解決と、サーバー内の処理の振り分けをつなぐ。ポート・パケット・TCP/QUICは閉じた補足に置く。
2. HTML・CSS・DOM：正式名称と各語の意味を説明してから、タグ・属性・スタイル指定の具体例へ進む。ソース、ブラウザ内の構造、表示結果を並べる。JavaScriptでDOMを書き換えても、受信したHTMLの文字列は変わらない。01の図にHTMLが先に出るため、初出でも正式名称と短い説明を添える。
3. JavaScriptとフレームワーク：スクリプト言語の意味と実行環境を説明し、開発時のMocha、初回公開時のLiveScript、JavaScriptの名称を区別する。開発者らによる歴史論文を参照する。イベント、状態、DOMの更新から、React・Vue・Svelte・Angularを紹介。Next.jsとNuxtは、それぞれReactとVueを利用したサイト全体の構築へつなぐ。言語、実行環境、ライブラリー、フレームワークの役割を混同しない。
4. バックエンドとデータベース：API、JSON、言語・実行環境・フレームワークの関係、メソッドとパスによるルーティング、RDB、行・列、主キー・外部キー、1対多とJOIN、SQL、保存と権限。Nginxなどによる振り分けと、アプリ内のルーティング、クライアント側の画面切り替えは補足で整理する。
5. CMSの仕組み：編集・保存・公開・取得、データとテンプレート、WordPress、ヘッドレスCMS。
6. 実際にインタラクションを実装するには？：入力・状態・表示・通信から実装を考える。ボタンとカードの小さなHTML例を動かしてから、DOM・SVG・Canvas・WebGL、D3とGSAP、ライブラリ導入、Three.jsとGPUの関係へ進む。ライブラリ等は10分野43件を公式資料で確認し、用途と種類を併記する。名前・用途で検索できるが、初期表示で全件を掲載する。

## 図と動作例

- 記事を開く通信図は、サーバーでHTMLを生成する構成に限定した説明。データの要求と応答を往復で表示し、手順ごとに処理する場所を強調する。
- HTML・DOM図は、要素と文字に絞った概念図。空白のテキストノードなどは省く。CSSの切替と、見出しのDOM変更を別々に操作する。
- JavaScriptの例は、標準のDOM操作とReactによる状態に応じた表示を比較する。表示するコードは抜粋であり、そのまま実行可能な完成プロジェクトではない。
- RDBの著者・記事は架空データ。WordPressの実際のスキーマではない。SQLと画面内のデータ処理は、同じ結合・絞り込み・並び順を表す。入力パラメーターをSQL文字列と分ける。
- CMSは画面内のシミュレーション。外部送信や永続保存は行わない。保存した下書き、公開中の版、読者が取得した版を別に保持し、操作の段階を区別する。公開後の改稿は下書きとして保存し、再公開まで旧版を保持する例。製品共通の仕様としては扱わない。
- CMS全般にRDBを必須とする説明は避け、PHPとMySQL/MariaDBはWordPressの例として扱う。
- ルーティング図は架空のAPI設計であり、ボタンは対応関係だけを切り替える。Expressのコードは抜粋で、公開記事を探す関数は実装する必要があると本文で示す。
- 06のカード例は単独のHTMLにCSSとJavaScriptを含める。同じファイルをsandbox付きiframeで表示し、ダウンロードできるようにする。通信・永続保存・外部ライブラリの読み込みはしない。キーボードでボタンを押せ、選択状態をaria-pressedに反映し、動きを減らす設定に対応する。
- ライブラリ一覧は紹介用の参照データ。列挙したライブラリを教材にインストールしたり自動読み込みしたりはしない。WebGLというブラウザAPI、Three.jsなどの道具、GPUというハードウェアを段階で結ぶ。

MDN、各フレームワークの公式資料、PostgreSQLとWordPressの公式ドキュメントを参照。バージョン番号や人気順位は教材に固定しない。章の補足は初期状態で閉じる。
